# Qwen3.5-35B-A3B Model Architecture Specification

This document details the architectural parameters, dimension shapes, and operation-level
specifications for **`Qwen/Qwen3.5-35B-A3B-FP8`** and **`Qwen/Qwen3.5-35B-A3B`** (BF16). All
symbols follow [NOTATION.md]({{reference:roofline-analysis/NOTATION.md}}) for use in roofline performance estimation.

**Sources.** Every hyperparameter below is read from the official checkpoint's `config.json`,
fetched from `https://huggingface.co/Qwen/Qwen3.5-35B-A3B-FP8/raw/main/config.json`.
Layer structure and fusion layout follow the vLLM implementation:

*   `vllm/model_executor/models/qwen3_5.py` — `Qwen3_5DecoderLayer`, `Qwen3_5Model`
*   `vllm/model_executor/models/qwen3_next.py` — `Qwen3NextAttention`, `Qwen3NextSparseMoeBlock`
*   `vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py` — `QwenGatedDeltaNetAttention`

> [!IMPORTANT]
> **Scope: the text decoder.** Like `Qwen3.5-397B-A17B`, the checkpoint is multimodal (`qwen3_5_moe`)
> and ships a Multi-Token Prediction (MTP) head (`mtp_num_hidden_layers: 1`); neither is on the
> text-only serving path unless explicitly enabled. See [§6](#6-out-of-scope-modules-vision-tower--mtp-head).

## 2. Layer Structure & Tensor Flow

Qwen3.5-35B-A3B is a **hybrid linear/softmax attention** model in which *every* layer is MoE.

*   **Attention sub-layers (3:1 interleaving, `full_attention_interval = 4`):**
    *   3 GDN linear-attention layers followed by 1 gated GQA layer, repeated 10 times across 40 layers.
    *   **GQA layers (0-indexed, 10 total):** $\{3, 7, 11, 15, 19, 23, 27, 31, 35, 39\}$, i.e. every layer with $\ell \bmod 4 = 3$.
    *   **GDN layers (0-indexed, 30 total):** all remaining layers.
    *   *Verified directly against the explicit 40-entry `layer_types` list in `config.json`.*
*   **FFN sub-layers:** all 40 layers are `Qwen3NextSparseMoeBlock` — Top-8 of 256 routed experts
    ($F_{\text{expert}} = 512$) **plus** 1 always-on shared expert
    ($F_{\text{shared}} = 512$) gated by a scalar sigmoid (`shared_expert_gate`).
*   **Residual/norm:** standard pre-norm. `input_layernorm` (RMSNorm) before attention,
    `post_attention_layernorm` (RMSNorm) before the MoE block, plain additive residuals.

```text
[Input: B x S x D = B x S x 2048]
       |
       +---> RMSNorm (input_layernorm)
       |
       +---> Attention Sub-Layer:
       |     ├── If GDN layer (30):  in_proj_qkv + in_proj_z + in_proj_b + in_proj_a
       |     |                       -> Conv1D(K=4, D_conv=8192, SiLU) -> L2Norm(q,k)
       |     |                       -> Gated Delta Rule kernel (H_v=32, D_k=128, D_v=128)
       |     |                       -> Gated RMSNorm(z)
       |     |                       -> out_proj [4096 -> 2048, RowParallel -> TP All-Reduce]
       |     └── If GQA layer (10):  qkv_proj (Q=4096 | gate=4096 | K=512 | V=512, fused 9216)
       |                             -> QK-RMSNorm -> partial RoPE (64 of 256)
       |                             -> Causal FlashAttention (paged KV, H_q=16, H_kv=2, D_h=256)
       |                             -> sigmoid(gate) * attn_out
       |                             -> o_proj [4096 -> 2048, RowParallel -> TP All-Reduce]
       |
       +---> Add attention residual
       |
       +---> RMSNorm (post_attention_layernorm)
       |
       +---> MoE Sub-Layer (all 40 layers):
       |     ├── Router: [2048, 256] (bf16) -> Top-8, renormalized
       |     ├── Routed experts: 256 x SwiGLU(2048 -> 512 -> 2048), fp8 block-quantized (or bf16)
       |     └── Shared expert: 1 x SwiGLU(2048 -> 512 -> 2048), scalar sigmoid gate [2048, 1] (bf16)
       |         (parallel branch on the same input; summed with the routed output)
       |
       +---> Add MoE residual
       |
[Output: B x S x D]
```

## 3. Sub-Component Operations & Tensor Shapes

### 3.1. Gated Delta Network (GDN) Sub-Layer — 30 Layers

Refer to the [GDN Roofline Skill]({{reference:roofline-analysis/model/common/attention/gdn/SKILL.md}}) for the operational
formulas. Note that $D_k = D_v = 128$, $H_{qk} = 16$, and $H_v = 32$ ($H_v / H_{qk} = 2$).

#### 1. QKV Projection (`in_proj_qkv`)

*   Weight: $[D,\ 2 H_{qk} D_k + H_v D_v] = [2048,\ 8192]$. Column-parallel.
*   Splits as `q` (2,048) | `k` (2,048) | `v` (4,096) — exactly $D_{\text{conv}} = 8{,}192$.
*   **FLOPs:** $2 B_{\text{local}} S \cdot D \cdot (2 H_{qk} D_k + H_v D_v)$.

#### 2. Z / B / A Gate Projections (`in_proj_z`, `in_proj_b`, `in_proj_a`)

Combined column-parallel width $H_v D_v + 2 H_v = 4{,}096 + 64 = 4{,}160$:

*   **`in_proj_z`** (RMSNorm gate): $[D,\ H_v D_v] = [2048,\ 4096]$ (fp8 in the FP8 checkpoint).
*   **`in_proj_b`** (write rate $\beta$): $[D,\ H_v] = [2048,\ 32]$ (`bf16` in `modules_to_not_convert`).
*   **`in_proj_a`** (decay $\alpha$): $[D,\ H_v] = [2048,\ 32]$ (`bf16` in `modules_to_not_convert`).
*   **FLOPs:** $2 B_{\text{local}} S \cdot D \cdot (H_v D_v + 2 H_v)$.

#### 3. Causal Depthwise 1D Convolution + SiLU

Refer to the [Conv1D Roofline Skill]({{reference:roofline-analysis/model/common/conv1d/SKILL.md}}).

*   $D_{\text{conv}} = 8{,}192$, $K_{\text{conv}} = 4$, SiLU activation, depthwise
    (`groups = D_conv`). Weight $[D_{\text{conv}}, 1, K_{\text{conv}}] = [8192, 1, 4]$ in `bf16`.
*   **Prefill FLOPs:** $2 B_{\text{local}} S \cdot D_{\text{conv}} \cdot K_{\text{conv}}$ (on VPU).
*   **Decode conv state:** $[B_{\text{local}},\ K_{\text{conv}} - 1,\ D_{\text{conv}}] = [B_{\text{local}}, 3, 8192]$.

#### 4. Gated Delta Rule Kernel

Applied after **L2 normalization of $q$ and $k$** (`l2norm_fwd`). See the GDN skill
[§4]({{reference:roofline-analysis/model/common/attention/gdn/SKILL.md}}) for prefill (chunk-wise) and decode (recurrent) formulas.

*   **Recurrent state:** $[B_{\text{local}},\ H_v,\ D_k,\ D_v] = [B_{\text{local}}, 32, 128, 128]$,
    held in **`float32`** (`mamba_ssm_dtype: "float32"`) — $2{,}097{,}152\text{ B} = \mathbf{2.0\text{ MiB}}$
    ($2.097\text{ MB}$) per sequence per GDN layer unsharded.
*   **Decode FLOPs:** $7 B_{\text{local}} H_v D_k D_v \approx 3.67\ B_{\text{local}}\text{ MFLOPs}$
    per GDN layer per step (VPU-bound / HBM state-read-bound in decode).

#### 5. Gated RMSNorm

*   `RMSNormGated(head_v_dim=128)` with **SiLU** activation:
    $o = \operatorname{SiLU}(z) \odot \operatorname{RMSNorm}(u)$, applied per V head over $[B_{\text{local}}, S, 4096]$.

#### 6. Output Projection (`out_proj`)

Refer to the [Output Projection Skill]({{reference:roofline-analysis/model/common/attention/out_proj/SKILL.md}}).

*   Weight: $[H_v D_v,\ D] = [4096,\ 2048]$. Row-parallel → **TP All-Reduce** of payload
    $B_{\text{local}} S D \times \text{bytes}$.
*   **FLOPs:** $2 B_{\text{local}} S \cdot H_v D_v \cdot D$.

### 3.2. Gated Full Attention (GQA) Sub-Layer — 10 Layers

Refer to the [QKV Projection]({{reference:roofline-analysis/model/common/attention/qkv_proj/SKILL.md}}),
[Global Attention]({{reference:roofline-analysis/model/common/attention/global_attention/SKILL.md}}) and
[Output Projection]({{reference:roofline-analysis/model/common/attention/out_proj/SKILL.md}}) skills.

> [!WARNING]
> **Two key differences from plain GQA:**
>
> 1.  **Output gate fused into QKV (`attn_output_gate = true`).** `qkv_proj` has output width
>     $(A_{\text{gate}} H_q + 2 H_{kv}) D_h = (2 \cdot 16 + 2 \cdot 2) \cdot 256 = 9{,}216$,
>     **not** the un-gated $(16 + 4) \cdot 256 = 5{,}120$ ($1.80\times$ larger).
> 2.  **Partial RoPE (`partial_rotary_factor = 0.25`).** Only $D_{\text{rope}} = 64$ of each head's
>     $D_h = 256$ channels are rotated.

#### 1. Fused QKV + Gate Projection (`qkv_proj`)

*   Weight: $[D,\ (A_{\text{gate}} H_q + 2 H_{kv}) D_h] = [2048,\ 9216]$. Column-parallel.
*   Splits as `q` (4,096) | `gate` (4,096) | `k` (512) | `v` (512).
*   **FLOPs:** $2 B_{\text{local}} S \cdot D \cdot (A_{\text{gate}} H_q + 2 H_{kv}) D_h$.

#### 2. Q/K Normalization and Partial RoPE

*   `q_norm`, `k_norm`: per-head `RMSNorm(D_h = 256)`, applied before RoPE.
*   RoPE rotates the first $D_{\text{rope}} = 64$ channels of each head.

#### 3. Causal Attention (paged / FlashAttention)

*   Q: $[B_{\text{local}}, S, H_q, D_h] = [B_{\text{local}}, S, 16, 256]$;
    K/V cache: $[B_{\text{local}}, S_{\text{kv}}, H_{kv}, D_h] = [B_{\text{local}}, S_{\text{kv}}, 2, 256]$.
*   **Prefill (causal) FLOPs:** QK phase $B_{\text{local}} S^2 H_q D_h$; AV phase $B_{\text{local}} S^2 H_q D_h$.
*   **Decode FLOPs ($S = 1$):** QK $2 B_{\text{local}} S_{\text{kv}} H_q D_h$; AV $2 B_{\text{local}} S_{\text{kv}} H_q D_h$.
*   **KV cache footprint:** $2 \cdot H_{kv} \cdot D_h = 1{,}024$ elements per token per GQA layer.
    See [§4.3](#43-kv-cache-and-recurrent-state-footprint).

#### 4. Output Gating

*   $\text{attn\_out} \leftarrow \sigma(\text{gate}) \odot \text{attn\_out}$, elementwise over
    $[B_{\text{local}}, S, H_q D_h = 4096]$.

#### 5. Output Projection (`o_proj`)

*   Weight: $[H_q D_h,\ D] = [4096,\ 2048]$. Row-parallel → **TP All-Reduce**.
*   **FLOPs:** $2 B_{\text{local}} S \cdot H_q D_h \cdot D$.

### 3.3. Sparse MoE Sub-Layer — All 40 Layers

Refer to the [MoE Roofline Skill]({{reference:roofline-analysis/model/common/moe/SKILL.md}}).

#### 1. Router (`mlp.gate`)

*   Weight: $[D,\ E] = [2048,\ 256]$, **`bf16`** (excluded from fp8). Replicated across devices.
*   Top-$K$ = 8, routing weights renormalized.
*   **FLOPs:** $2 B_{\text{local}} S \cdot D \cdot E$.

#### 2. Routed Experts (256 experts, Top-8, SwiGLU)

*   **W1 gate/up (fused):** per expert $[D,\ 2 F_{\text{expert}}] = [2048,\ 1024]$.
    **FLOPs:** $4 B_{\text{local}} S K \cdot D \cdot F_{\text{expert}}$.
*   **Activation:** SiLU-GLU (`hidden_act: "silu"`).
*   **W2 down:** per expert $[F_{\text{expert}},\ D] = [512,\ 2048]$.
    **FLOPs:** $2 B_{\text{local}} S K \cdot F_{\text{expert}} \cdot D$.
*   **Total routed FLOPs:** $6 B_{\text{local}} S K \cdot D \cdot F_{\text{expert}}$.
*   **Weight bytes per layer:** $E \cdot 3 \cdot D \cdot F_{\text{expert}} = 256 \cdot 3 \cdot 2048 \cdot 512 = 805.31\text{ M}$
    parameters $= 805.31\text{ MB}$ at 1 byte (fp8) or $1.611\text{ GB}$ at 2 bytes (bf16), divided by $\text{TP} \times \text{EP}$.

#### 3. Shared Expert (1, always active)

*   `shared_expert_gate`: $[D, 1] = [2048, 1]$, **`bf16`**, scalar sigmoid applied to the shared branch output.
*   **W1 gate/up:** $[D,\ 2 F_{\text{shared}}] = [2048,\ 1024]$;
    **W2 down:** $[F_{\text{shared}},\ D] = [512,\ 2048]$.
*   **FLOPs:** $6 B_{\text{local}} S \cdot D \cdot F_{\text{shared}}$ (no $K$ factor).

## 4. Precision, Quantization & Memory Footprint

### 4.1. Data Types

In `Qwen/Qwen3.5-35B-A3B-FP8`, `quantization_config` specifies `quant_method: "fp8"`,
**block-wise `[128, 128]`**, `activation_scheme: "dynamic"`.

The `modules_to_not_convert` list across all 40 layers keeps the following modules in `bf16`:

| Scope | Modules kept in `bf16` |
| :--- | :--- |
| All 30 GDN layers | `linear_attn.conv1d`, `linear_attn.in_proj_a`, `linear_attn.in_proj_b`, `mlp.gate`, `mlp.shared_expert_gate` |
| All 10 GQA layers | `mlp.gate`, `mlp.shared_expert_gate` |
| Global | `lm_head`, `embed_tokens`, the entire vision tower (`model.visual.*`), `mtp.fc`, `mtp.layers.0.linear_attn.{conv1d,in_proj_a,in_proj_b}`, `mtp.layers.0.mlp.{gate,shared_expert_gate}` |

### 4.2. Arithmetic Intensity of the Routed-Expert GEMMs

Using the [MoE skill]({{reference:roofline-analysis/model/common/moe/SKILL.md}})'s formula with
$N_{\text{local}} = B_{\text{local}} S$ local tokens and expert parallelism $\text{EP}$:

$$\text{AI} \;=\; \frac{6 N_{\text{local}} K D F_{\text{expert}}}{(E/\text{EP}) \cdot 3 D F_{\text{expert}} \cdot b_w} \;=\; \frac{2 N_{\text{local}} K \cdot \text{EP}}{E \cdot b_w}$$

At $K = 8$, $E = 256$:
*   For $\text{EP} = 1$ (pure TP across $T$ devices, where each expert's $(D, F_{\text{expert}})$ is sharded by $T$):
    $\text{AI} = \frac{2 N_{\text{local}} K}{E \cdot b_w} = \frac{16 N_{\text{local}}}{256 \cdot b_w} = \frac{N_{\text{local}}}{16 \cdot b_w}$ FLOP/byte.
*   For $\text{EP} = 8$ (experts partitioned 32 per device):
    $\text{AI} = \frac{2 N_{\text{local}} \cdot 8 \cdot 8}{256 \cdot b_w} = \frac{0.5 N_{\text{local}}}{b_w}$ FLOP/byte.

Against the [TPU v7x P3 derated]({{reference:roofline-analysis/tpu/V7X.md}}) per-chiplet (per-device) machine balance
(FP8: $1{,}785.6\text{ TFLOPS}$, BF16: $892.8\text{ TFLOPS}$, HBM: $3{,}364.9\text{ GB/s}$):

| Precision & Layout | Peak FLOPS | Balance point | Crossover $N_{\text{local}}$ ($\text{EP}=8$) | Crossover $N_{\text{local}}$ ($\text{EP}=1$) |
| :--- | ---: | ---: | ---: | ---: |
| **FP8** ($b_w = 1\text{ B}$) | $1{,}785.6\text{ TFLOPS}$ | $530.7$ FLOP/B | $\approx 1{,}062$ tokens | $\approx 8{,}491$ tokens |
| **BF16** ($b_w = 2\text{ B}$) | $892.8\text{ TFLOPS}$ | $265.3$ FLOP/B | $\approx 1{,}062$ tokens | $\approx 8{,}491$ tokens |

> [!NOTE]
> **MXU contracting-dimension padding.** [REQUIREMENTs.md]({{reference:roofline-analysis/model/common/REQUIREMENTs.md}}) requires
> ceil-padding any contracting dimension below the v7x minimum of **256**. In `Qwen3.5-35B-A3B`:
> *   Unsharded $D = 2{,}048$, $F_{\text{expert}} = F_{\text{shared}} = 512$, and $D_h = 256$ are all $\ge 256$.
> *   However, when $F_{\text{expert}} = 512$ or $F_{\text{shared}} = 512$ is sharded along the contracting dimension by $\text{TP} \ge 4$ (for example, `W2 down` with $\text{TP} = 4 \implies F_{\text{local}} = 128$, or $\text{TP} = 8 \implies F_{\text{local}} = 64$), the per-device contracting dimension falls below 256 and suffers a $2\times$ ($\text{TP}=4$) or $4\times$ ($\text{TP}=8$) MXU padding penalty unless EP is used for routed experts!

### 4.3. KV Cache and Recurrent State Footprint

For one sequence at context length $S$ (unsharded across the model):

1.  **GQA KV cache (10 layers):**
    $$L_{\text{gqa}} \cdot S \cdot 2 H_{kv} D_h \cdot b_{\text{kv}} = 10 \cdot S \cdot 1024 \cdot b_{\text{kv}} = 10{,}240 \cdot S \cdot b_{\text{kv}}\text{ B}$$
    *   At $b_{\text{kv}} = 1$ B (fp8): $10{,}240\text{ B} = \mathbf{10.0\text{ KiB per token}}$ ($93.75\text{ MB}$ at $S = 9{,}216$).
    *   At $b_{\text{kv}} = 2$ B (bf16): $20{,}480\text{ B} = \mathbf{20.0\text{ KiB per token}}$ ($187.50\text{ MB}$ at $S = 9{,}216$).
    *   *Important TP replication note:* Since $H_{kv} = 2$, at $\text{TP} > 2$ ($\text{TP} \in \{4, 8\}$), each device holds $\max(1, 2 // \text{TP}) = 1$ KV head. Thus per-device GQA KV cache is $5.0\text{ KiB/tok}$ (fp8) for all $\text{TP} \in \{2, 4, 8\}$.
2.  **GDN recurrent state (30 layers), $O(1)$ in $S$:**
    $$L_{\text{gdn}} \cdot H_v D_k D_v \cdot 4\text{ B} = 30 \cdot 32 \cdot 128 \cdot 128 \cdot 4 = \mathbf{62{,}914{,}560\text{ B}} = \mathbf{60.0\text{ MiB}} \ (\mathbf{62.91\text{ MB}})\text{ per sequence}$$
3.  **GDN conv state (30 layers), $O(1)$ in $S$:**
    $$L_{\text{gdn}} \cdot (K_{\text{conv}} - 1) \cdot D_{\text{conv}} \cdot 2\text{ B} = 30 \cdot 3 \cdot 8192 \cdot 2 = \mathbf{1{,}474{,}560\text{ B}} = \mathbf{1.41\text{ MiB}} \ (\mathbf{1.47\text{ MB}})\text{ per sequence}$$

> [!IMPORTANT]
> The $64.39\text{ MB}$ ($61.41\text{ MiB}$) of $S$-independent GDN state per sequence (divided by $\text{TP}$ across ranks, since $H_v = 32$ shards cleanly up to $\text{TP} = 32$) is paid in full for every active slot regardless of sequence length. At $S = 9{,}216$ (8K input + 1K output) and $\text{TP} = 1$, a single sequence's state is $94.37\text{ MB}$ GQA KV (fp8) + $64.39\text{ MB}$ GDN state = **$158.76\text{ MB}$/seq** ($0.148\text{ GiB}$/seq). See the [Memory Usage Skill]({{reference:roofline-analysis/memory_usage/SKILL.md}}).

## 6. Out-of-Scope Modules: Vision Tower & MTP Head

*   **Vision tower** (`vision_config`): 27 blocks, $d = 1{,}152$, intermediate $4{,}304$, 16 heads,

    `--language-model-only` serving paths.

## 7. Parallelism Strategies on TPU v7x (`2x2x1` = 4 Chips / 8 Devices, and `1x1x1` = 1 Chip / 2 Devices)

Per TPU v7x architecture ([V7X.md]({{reference:roofline-analysis/tpu/V7X.md}})), each TPU7x chip has **2 chiplets (devices)**, each with 1 TensorCore and $96\text{ GB}$ ($89.41\text{ GiB}$) of HBM.
*   A **`1x1x1` (1-chip) slice** provides **2 TPU7x devices** ($192\text{ GB}$ HBM total), natural for $\text{TP}=2, \text{DP}=1$.
*   A **`2x2x1` (single-host 4-chip) slice** provides **8 TPU7x devices** ($768\text{ GB}$ HBM total), supporting $\text{TP} \times \text{DP} = 8$ with optional Expert Parallelism ($\text{EP} \in \{1, 2, 4, 8\}$).

### 7.1. Tensor Parallelism (TP)

*   **GDN (30 layers):** $H_{qk} = 16$ and $H_v = 32$ shard evenly across $\text{TP} \in \{1, 2, 4, 8, 16\}$.
*   **GQA (10 layers):** $H_q = 16$ shards evenly up to $\text{TP} = 16$, while **$H_{kv} = 2$ replicates for $\text{TP} > 2$** (`kv_per_rank = max(1, 2 // TP) = 1` for $\text{TP} \in \{2, 4, 8\}$).
*   **MoE (40 layers):** Without EP ($\text{EP} = 1$), TP shards $F_{\text{expert}} = 512$ across ranks. For $\text{TP} \ge 4$, $F_{\text{expert}} / \text{TP} \le 128 < 256$, incurring MXU contracting-dimension padding on `W2 down`. Combining $\text{TP} \in \{1, 2\}$ with $\text{EP}$ (or running $\text{DP}$ replicas of $\text{TP}=1$ or $\text{TP}=2$ since the $34.66\text{ GB}$ FP8 weights easily fit on 1 or 2 devices) avoids MXU under-padding.

### 7.2. Expert Parallelism (EP)

*   256 routed experts partition evenly across $\text{EP} \in \{1, 2, 4, 8\}$: $E_{\text{local}} = 256 / \text{EP}$ ($32$ experts per device at $\text{EP} = 8$, or $100.7\text{ MB}$ of fp8/int8 expert weights per device per layer).

### 7.3. TPU v6e (Trillium) Single-Host (`v6e-8` = 8 Chips / 8 Devices) Rules

On TPU v6e (`ct6e-standard-8t`, 8 chips = 8 devices, $32\text{ GB}$ HBM / $1{,}638\text{ GB/s}$ per chip, $918\text{ TFLOPS}$ BF16 MXU, $1{,}836\text{ TOPS}$ INT8 MXU, no $2\times$ FP8 MXU acceleration):
*   **Parallelism (`DP=8 + EP=8` over `TP=8 + EP=8`):** `DP=8 + TP=1 + EP=8` is $1.5\times$ to $1.9\times$ faster than the official single-host recipe's `TP=8 + EP=8` ($9{,}698 / 7{,}913 / 6{,}040\text{ tok/s}$ vs. $6{,}336 / 5{,}024 / 3{,}190\text{ tok/s}$ at $819 / 3{,}482 / 7{,}373$ input tokens) because $\text{TP}=8$ shards $F_{\text{shared}} = 512$ down to $64 < 256$ and adds 80 cross-chip AllReduces per step.
*   **Native W8A8 INT8 MoE & Dense Linear on `tpu-inference` (`vllm/vllm-tpu:v0.32.0`):** Because TPU v6e runs `float8_e4m3fn` weights at the BF16 MXU rate ($918\text{ TFLOPS}$) with software conversion overhead, serve from the unquantized `Qwen/Qwen3.5-35B-A3B` (BF16) checkpoint and enable online INT8 quantization:
    *   `MOE_REQUANTIZE_WEIGHT_DTYPE=int8` and `MOE_REQUANTIZE_BLOCK_SIZE=512`: block-quantizes all 256 routed experts to `jnp.int8` at load time ($8.05\text{ GB} \to 4.03\text{ GB/chip}$, freeing $171.47\text{ GiB}$ KV cache across the host) and activates the `tokamax` `gmm_v2` native INT8 MXU path (`lhs_q_dtype = jnp.int8`, `int8 x int8 -> int32` on the $1{,}836\text{ TOPS}$ MXU), reaching $11{,}578 / 7{,}933 / 5{,}157\text{ tok/s}$ ($+19.4\%$ over TorchTPU BF16 at $819$ ISL and $+22.3\%$ over JAX FP8 at $7{,}373$ ISL) and cutting pure decode step ITL at $3{,}482$ ISL from $22.35\text{ ms}$ (BF16) to $18.39\text{ ms}$ ($1.22\times$ faster, steady-state engine generation peak $16{,}595\text{ tok/s}$ host $= 4{,}149\text{ tok/s}$ per $2$ devices $= 0.99\times$ of $2\times\text{H100}$ BF16).
    *   `BF16_LINEAR_REQUANTIZE_PATTERNS="re:.*\.(qkv_proj|o_proj|in_proj_qkvz|out_proj|gate_up_proj|down_proj)$"` and `BF16_LINEAR_REQUANTIZE_WEIGHT_DTYPE=int8`: quantizes dense projections to per-channel `jnp.int8` on the INT8 MXU via `xla_quantized_matmul`, expanding the host KV cache pool to $181.92\text{ GiB}$ ($22.74\text{ GiB/device}$) and reaching $11{,}889 / 7{,}921 / 5{,}101\text{ tok/s}$ ($+22.6\%$ over TorchTPU BF16 at $819$ ISL).
    *   *Upstream `tpu-inference` scale-forwarding bug (`v0.32.0`):* In `tpu_inference/layers/vllm/quantization/unquantized.py` (`VllmUnquantizedFusedMoEMethod`, lines 701–728), `process_unquantized_moe_weights` returns `weights.w13_weight_scale` and `weights.w2_weight_scale` when `MOE_REQUANTIZE_WEIGHT_DTYPE=int8` is set, but `VllmUnquantizedFusedMoEMethod` omitted saving them on `layer` and passed `w13_weight_scale=None, w2_weight_scale=None` in `apply_monolithic` (unlike `layers/jax/quantization/unquantized.py` lines 272–277). Patch `VllmUnquantizedFusedMoEMethod` to store and pass both scales so `gmm_v2` dequantizes the `int32` accumulator properly; with this 8-line fix, 1,400-sample MMLU-Pro reaches $0.7700 \pm 0.0110$ on W8A8 INT8 MoE ($-0.29\text{ pp}$ vs. GPU BF16 $0.7729 \pm 0.0110$) and $0.7664 \pm 0.0110$ on Full W8A8 INT8 Dense+MoE ($-0.65\text{ pp}$ vs. GPU BF16).
*   **Scheduler & KV Cache Pitfalls on v6e:**
    *   Always pass `--kv-cache-dtype=fp8_e4m3` explicitly (`--kv-cache-dtype=fp8` is silently mapped to `fp8_e5m2` on v6e).
    *   On `tpu-inference` with `enable_dp_attention`, set `DP_SCHED_BATCH_PREFILL=0` and `DP_SCHED_ROUTING=round_robin` (otherwise `DP_SCHED_BATCH_PREFILL=True` holds $< 8$ remainder requests in `_pending_new_requests` for up to $30\text{ s}$, adding an $18\text{ s}$ straggler tail; disabling it cuts tier durations from $72.6 / 72.9 / 87.6\text{ s}$ to $58.3 / 59.5 / 77.2\text{ s}$, boosting E2E throughput by $+21.3\% \sim +26.2\%$), and size `--max-num-seqs=48` and `--max-num-batched-tokens=2048` per DP rank so the FP32 GDN recurrent state pool and MoE precompile buckets fit in $32\text{ GB}$ HBM.
